# Habulan Rush Upgrade Audit

Audit date: 2026-10-15  
Scope: static repository audit and proposals only. No game code, configuration, logs, or generated place files were changed.

## 1. Summary

- OpenCode should load the root `AGENTS.md` and discover `.agents/skills` on demand, but it will not automatically load `.gemini/TASK.md` or `.gemini/PLANNING.md`.
- There is no repository OpenCode configuration, and the installed OpenCode 1.19.0 CLI currently fails before startup with an `EEXIST` directory error.
- `AGENTS.md` is useful but too broad for always-on context, contains stale folder claims, and describes conventions that the mapped production files do not consistently follow.
- The live task tracker is a backlog, not a safe handoff: implemented work is still unchecked and Current, Next, Blockers, and Validation are not obvious.
- The match shell, Kalsada greybox, movement presentation, HUD, settings controls, RS_01, and RS_03 are substantial, but the complete game loop is not release-ready.
- The most serious gameplay risks are role-source disagreement, an over-range client tag endpoint, missing authoritative pounce and dash handling, and debug bypasses enabled in `Config`.
- Sprint and slide animation assets and neon sprint VFX exist, but asset provenance, scale math, camera ownership, and mobile-off behavior need repair.
- Audio and settings are wired, but settings are not saved and most active audio plus all published animation IDs lack completed competition approval records.
- Highest priority is workflow recovery, compliance gating, server authority, then small feel and presentation passes validated with two live clients.

## 2. Setup findings and proposed setup changes

### OpenCode and context behavior

OpenCode documents that a project `AGENTS.md` is loaded as an instruction file, while referenced files are not automatically expanded unless they are configured as instructions or the agent explicitly reads them. It also discovers `.agents/skills/<name>/SKILL.md` and loads a selected skill on demand. See [OpenCode rules](https://docs.opencode.ai/docs/rules/) and [OpenCode skills](https://docs.opencode.ai/docs/skills/). Therefore the root instructions should be available, but `.gemini/TASK.md`, `.gemini/PLANNING.md`, ownership, logs, and design documents depend on the agent following written directions. The repository contains no `opencode.json`, `opencode.jsonc`, or `.opencode/` configuration. `.zcode/config.json` belongs to another client and does not configure OpenCode. Repository-local configuration was audited; user-global OpenCode configuration was not available in this workspace audit.

The installed package reports OpenCode 1.19.0, but `opencode --version` fails with `EEXIST: file already exists, mkdir C:\Users\Acer\.local\share\opencode`. This prevents a direct proof that this machine currently loads the repository instructions. Repair and a smoke test are required before relying on OpenCode for a handoff.
